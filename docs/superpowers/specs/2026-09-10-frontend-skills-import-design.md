# Frontend Skills Import — Design

## Status

Conversation-approved design for the first repository update tranche. This
document covers only `impeccable` and `ui-ux-pro-max`. `caveman` and
`how-to-use-codex` are separate follow-up work; Graph Engineering v5.2 is
deferred until validated.

## Goal

Make the public Agentic Engineering Skills pack useful for frontend work by
shipping the currently used `impeccable` and `ui-ux-pro-max` skill packages
with complete runtime assets, honest provenance, license notices, discovery
metadata, and reproducible validation.

## Scope

### In scope

- Import the complete active `impeccable` package, including its `SKILL.md`,
  references, scripts, and agent configuration.
- Import the complete active `ui-ux-pro-max` package, including its
  `SKILL.md`, scripts, and searchable data files.
- Add both skills to the canonical inventory and plugin inventory.
- Record source classification, source revision or local-source rationale,
  file hashes, and applicable license/notice material.
- Update selective-install documentation and the README's frontend workflow
  description.
- Extend existing pack, public-audit, manifest, and native-discovery tests so
  missing assets, extra assets, stale inventory, or undisclosed private
  material fail validation.

### Out of scope

- Editing the behavior of either imported skill beyond portability metadata
  required by this repository's host contract.
- Adding Graph Engineering v5.1 or the unfinished v5.2 skill.
- Updating `caveman`, `how-to-use-codex`, `writing-plans`, or the execution
  workflow in this tranche.
- Changing the Alfe application or its local project skills.
- Publishing, pushing, or creating a release without a separate owner gate.

## Source and packaging decisions

The import source is the active local skill package used for the workflow. The
directory layout remains intact so references and scripts resolve without
rewriting. The two packages are treated as bundled skill assets, not reduced
to their top-level Markdown files.

Each skill gets an explicit provenance entry. If a source repository and
revision are available, they are pinned. If the active package is a local
adaptation or composite package, the manifest records that fact and the
repository-owned change notice explains why a source revision cannot be
claimed. No unverified upstream identity is invented.

License and notice files are copied or generated only after the source license
is verified. Third-party material remains under its original terms; repository
original adaptation material remains under the repository's MIT terms.

## Integration surfaces

The implementation updates the smallest existing surfaces required by the
pack contract:

- `plugins/agentic-engineering-skills/skills/`
- `manifests/skill-sources.json`
- `manifests/skills.lock.json`
- `manifests/native-discovery.json`
- `tests/expected-inventory.mjs`
- plugin, manifest, provenance, license, CI, and public-audit contract tests
- `docs/provenance.md`, `docs/selective-install.md`, and relevant workflow
  documentation
- `README.md` with a concise frontend route and usage pointers

Generated receipts and hashes must be regenerated by repository scripts, not
hand-edited. Existing inventory ordering and naming conventions remain the
source of truth.

## Validation

Acceptance requires all of the following:

1. Both skill names appear exactly once in the expected inventory and are
   discoverable on Codex and Claude Code in the isolated native checks.
2. Every referenced file exists; no required reference, script, agent config,
   or dataset is omitted.
3. Pack hashes, provenance, license/notice records, and installed receipts
   agree with the tracked source bytes.
4. The public audit passes without private paths, credentials, local-only
   endpoints, unresolved legal placeholders, or generated release archives.
5. The full repository test command, pack verification, and public audit pass.
6. README instructions describe the frontend skills accurately and do not
   imply that installing them alone proves fresh-session invocation.

## Failure handling

If a license, upstream revision, source asset, or native discovery result is
unclear, stop import for that skill and report the exact missing evidence.
Never guess provenance or silently drop a runtime dependency. If validation
finds drift, repair the manifest or source package, rerun the complete checks,
and do not claim the tranche ready until all receipts converge.
